# OSCAR Expert implementation plan

2026-10-12. Baseline: `npm run verify`, 168 tests plus synthetic smoke passed.
Reviewed the shared React shell, preload/REST adapters, read-only OscarQueries,
schema v7/migrations, profiles, settings, daily raw-sample analysis and existing
Daily/API/security tests. Official MCP v2 docs and npm report server/client 2.3.1.

## Boundaries

- A profile/machine-scoped ExpertTools service delegates to existing daily,
  overview/statistics and elapsed-time-weighted channel calculations. It opens
  SQLite read-only, never migrates or creates it, and validates profile ownership.
- One typed Zod registry serves the direct orchestrator and stdio MCP adapter.
  Validate dates, channels, bounded ranges/windows and output sizes. No arbitrary
  SQL, paths, shell commands, session changes or raw waveform arrays are tools.
- Evidence includes scope, therapy dates and optional wall-clock windows; only
  evidence actually generated by tools may appear in accepted observations.
  Findings are descriptive arithmetic, not diagnoses or prescribed changes.
- Reuse existing raw-sample channel analysis for bounded windows. Unsupported
  derived respiratory/clinical algorithms are omitted explicitly.

## Ollama and reviews

- Native Node fetch against official Ollama HTTP APIs; backend-only, literal
  loopback endpoint, no credentials/redirects/remote endpoint/cloud fallback.
  Reject cloud model markers/metadata; document disabling Ollama cloud features.
- Opt-in settings alongside the database in a separate application config file
  (not clinical data). Installed-model selection, optional context size, synthetic
  chat/tool/JSON compatibility checks. Model verification before health data.
- Controlled, cancellable tool loop (12 calls, two identical calls, 180-second
  total budget), request-scoped caches and bounded context/response sizes.
- Structured Zod review schema, evidence validation, confidence constraints,
  explicit educational scope and no treatment instructions. Results ephemeral.
  Log only names/counts/timings/status, never prompts, tool payloads or responses.
- Status actions only; no hidden reasoning displayed. Review job polling supports
  both scoped IPC and authenticated REST; cancellation stops generation.

## UI and adapters

- Expert navigation with settings/compatibility, night/trend/question reviews,
  progress/cancellation, validated results and evidence links to Daily/windows.
  Shared React UI for both deployments. Browser Ollama runs on the server host.
- Update OpenAPI/preload/types/REST contract and integration tests together.
  Bind jobs to requesting renderer/session scope; invalidate on scope changes.
- Stdio MCP is a separate opt-in executable, scoped to one profile and machine.
  Host launches it; no misleading app-managed enabled switch. Resolve database
  via explicit deployment config or documented default desktop location. MCP
  resources/prompts are minimal; HTTP transport remains optional future work.
  External MCP hosts control their own data handling and may use cloud models.

## Performance, RAG and validation

- No full-night waveform context. Aggregate trend summaries, request-local reuse,
  bounded tool results. Record tool versus generation and total times separately.
- NoKnowledgeProvider with citation-ready interface; no fake reference citations,
  embeddings, downloads or Internet tools in the product.
- Synthetic tool/domain/privacy/read-only/profile/session/summary regression
  tests; fake LLM orchestration and local fake Ollama HTTP tests; real SDK stdio
  client parity/enumeration tests; API integration/auth/cancellation checks.
- Root verification, both renderer builds/typecheck, synthetic UI checks and
  optional actual local Ollama compatibility/review only if available. Record
  missing real-model/hardware/installer validation plainly.
